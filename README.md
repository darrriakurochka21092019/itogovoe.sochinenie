# Мастерская сочинения

Закрытое приложение для одного преподавателя и небольшой группы одиннадцатиклассников. Интерфейс полностью на русском языке. Регистрации для посторонних нет.

## Быстрый запуск из GitHub

Клонируйте репозиторий и соберите серверную версию:

```bash
git clone https://github.com/darrriakurochka21092019/itogovoe.sochinenie.git
cd itogovoe.sochinenie
npm ci
npm run check
npm run build:standalone
```

Далее скопируйте `.env.example` в `.env`, задайте случайный `SETUP_TOKEN` и выполните:

```bash
node --env-file=.env standalone-dist/server/server.js
```

Сайт откроется по адресу **http://127.0.0.1:3000**. Настройка преподавателя, создание учеников и размещение на своём домене описаны ниже.

## Что работает

- Две роли с серверной проверкой доступа. Преподаватель создаёт учеников, задаёт временный пароль, сбрасывает пароль и закрывает доступ. Ученик обязательно заменяет временный пароль при первом входе.
- Пароли: PBKDF2-HMAC-SHA256, 600 000 итераций, отдельная случайная соль. На серверах с ограничением нативного PBKDF2 используется совместимая реализация того же алгоритма с теми же 600 000 итераций. Сессионные токены хранятся в базе только как SHA-256. Cookie HttpOnly, SameSite=Lax, Secure при HTTPS; CSRF-защита, ограничение попыток входа, завершение сессий при сбросе пароля.
- Видеоуроки с конспектом, сохранением позиции просмотра, скоростью 0.5–2× и практикой. Нативный видеоплеер поддерживает паузу, перемотку и полный экран. Завершение урока ученик отмечает самостоятельно.
- Все восемь типов заданий: выбор одного/нескольких ответов, соответствия, последовательность, поиск ошибки, правда/вымысел, конструктор аргумента, короткий ответ и сочинение.
- Автоматическая проверка однозначных заданий на сервере, объяснения, история попыток, лимиты. Правильные ответы не передаются ученику до отправки попытки.
- Черновики письменных ответов с автосохранением и явной кнопкой сохранения. При переходе через меню приложение дожидается сохранения. При закрытии вкладки с несохранённым текстом браузер предупреждает об этом.
- Проверка учителем: общий комментарий, сильные стороны, темы для повторения, комментарии по пяти критериям, принятие и возврат на доработку. Доработку можно отправить сверх исходного лимита попыток.
- Личные результаты, библиотека с поиском и фильтрами, назначение заданий всем или конкретному ученику, календарь открытия 28 дней по московскому времени.
- Визуальные редакторы уроков, заданий всех типов, произведений и календаря. Снимок задания в истории сохраняет формулировку и ответы на момент отправки, даже если преподаватель изменил материал позже.
- Выгрузка учебных данных в JSON из раздела «Ученики». Экспорт не включает пароли, их хеши, сессии и неотправленные черновики.

## Стартовые материалы

8 уроков с краткими конспектами, без фиктивных видео. 28 дней объединены в четыре недели. В первых 8 днях — по одному полноценному демонстрационному заданию каждого типа. Дни 9–28 пока скрыты и предназначены для ваших материалов. Ещё 6 коротких тестов привязаны к шести произведениям библиотеки.

Список произведений: «Капитанская дочка», «Евгений Онегин», «Герой нашего времени», «Преступление и наказание», «Война и мир», «Ионыч». Карточки содержат ссылки на тексты. Литературные аргументы — авторские направления рассуждения; они не выдаются за цитаты. Сведения о критериях сопровождаются ссылкой на [ФИПИ](https://fipi.ru/itogovoe-sochinenie).

Показатели прогресса основаны на сохранённых данных. Задание считается выполненным после 100% в однозначном упражнении или принятия письменной работы преподавателем. День завершён, когда выполнены все доступные ученику задания этого дня. Программа = завершённые дни и уроки / (28 + количество опубликованных уроков). Показателя «готовности к экзамену» нет. Счётчик слов технический: последовательности букв/цифр с внутренним дефисом считаются одним словом; он не заменяет ручной подсчёт при официальной проверке.

## Два способа запуска

1. **Самостоятельный Node.js-сервер.** React + TypeScript + Vite + Tailwind + Lucide, Node.js и обычный SQLite-файл. Видео хранятся в каталоге сервера. Ученики открывают ваш домен и входят по логину и паролю; ChatGPT и внешняя авторизация не нужны.
2. **Размещённая версия Sites.** Тот же интерфейс и API в Vite/Vinext, SQLite-совместимая D1 и R2 для видео. Эта опубликованная версия изначально доступна только владельцу через дополнительную платформенную авторизацию. Она удобна для знакомства и настройки, но её ссылка сама по себе не выдаёт доступ трём ученикам. Для самостоятельной работы группы без аккаунтов ChatGPT используйте Node.js-версию на своём сервере.

Данные этих установок независимы. Перенос между D1 и обычным SQLite автоматически не выполняется. Выберите установку для реального обучения до добавления учеников.

## Локальный запуск: самый короткий путь

Нужен **Node.js 24 LTS**. В архиве уже есть собранная папка `standalone-dist`; для запуска этой сборки установка npm-пакетов не требуется.

1. Распакуйте архив в отдельную папку и откройте в ней PowerShell/терминал.
2. Скопируйте `.env.example` в `.env`:

```powershell
Copy-Item .env.example .env
```

macOS / Linux:

```bash
cp .env.example .env
```

3. Сгенерируйте случайный код настройки:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Вставьте выведенное значение в `.env` после `SETUP_TOKEN=`. Это одноразовое условие создания первого преподавателя. Не публикуйте `.env`.

4. Запустите:

```bash
node --env-file=.env standalone-dist/server/server.js
```

5. Откройте **http://127.0.0.1:3000**. На странице первого запуска укажите имя преподавателя, придумайте логин и уникальный пароль от 12 символов, введите код из `SETUP_TOKEN`. Создастся ровно одна учётная запись преподавателя и стартовые материалы. Готовых общих паролей нет.

Если собранной папки нет или вы меняли исходный код, сначала выполните:

```bash
npm ci
npm run check
npm run build:standalone
```

После этого запускайте той же командой `node --env-file=.env standalone-dist/server/server.js`. При повторном запуске данные сохраняются в `data/`. Не удаляйте этот каталог.

Если порт занят, измените `PORT` и `APP_ORIGIN` в `.env` согласованно, например на `3002` и `http://127.0.0.1:3002`.

## Создать трёх учеников

1. Войдите преподавателем, откройте «Ученики» → «Добавить ученика».
2. Укажите имя, отдельный логин латиницей и временный пароль не короче 12 символов.
3. Повторите ещё два раза. Логины должны отличаться.
4. Лично передайте каждому ученику его логин, временный пароль и адрес сайта.
5. При первом входе ученик меняет пароль. После этого у него появляется собственный кабинет с нулевым прогрессом.

Преподаватель не видит действующие пароли. Для сброса откройте карточку ученика → «Управление доступом» и задайте новый временный пароль. Все старые сессии этого ученика завершатся. Отключение «Доступ ученика активен» закрывает вход, сохраняя результаты.

## Работа преподавателя

**Видео.** «Уроки» → значок карандаша. Заполните название, цель и конспект, выберите файл или добавьте прямую ссылку. Установите «Опубликовать для учеников». Файлы: MP4, WebM, Ogg, до 64 МиБ. Для совместимости обычно подходит MP4 с H.264/AAC. Наличие MP4-контейнера не гарантирует поддержку любого кодека на всех устройствах. Для более крупных роликов используйте прямую HTTPS-ссылку на видеофайл с разрешённым воспроизведением с вашего сайта; страница видеосервиса не является прямой ссылкой. Ссылка на внешний файл доступна ученикам в коде плеера; для закрытого доступа к файлу загружайте его в приложение.

**Задание.** «Задания» → «Создать задание». Выберите тип, добавьте формулировку и содержание. В тестах укажите правильные ответы и объяснение. Упорядоченные блоки внесите в верном порядке — ученику они будут перемешаны. Для конструктора заполните четыре подписанных смысловых блока. При необходимости выберите день, урок, произведение и конкретного ученика. Материал должен быть опубликован, а связанные урок и произведение — доступны ученику.

**День.** «Задания» → «Календарь · 28 дней». Откройте карточку, задайте дату по Москве или нажмите «Открыть сейчас», затем сохраните. День без опубликованных заданий отображается ученику как готовящийся материал.

**Письменные ответы.** «На проверке» → работа ученика. Оставьте комментарий, при желании заполните сильные стороны, темы для повторения и обратную связь по критериям. «Принять работу» завершает её; «Вернуть на доработку» открывает редактирование ученику. Для возврата нужен комментарий. Проверка старой версии после новой отправки блокируется.

**Библиотека.** Добавляйте/редактируйте карточки. Темы указывайте через запятую, источники — по одному на строку. Тест создаётся отдельно в редакторе заданий с привязкой к произведению.

## Размещение в интернете на своём сервере

Для доступа школьников из России можно разместить Node.js-версию у выбранного вами российского хостера. Нужен небольшой Linux-сервер с постоянным диском, домен, Docker с Compose и открытые порты 80/443. Реальный расход диска зависит прежде всего от ваших видео; обязательных внешних платных API у приложения нет. Доступность конкретного хостера, цену и связь с домашними сетями учеников нужно проверить перед оплатой.

1. Направьте A-запись своего домена на IP сервера. Загрузите проект в отдельный каталог.
2. Создайте `.env` на сервере:

```dotenv
SETUP_TOKEN=ЗДЕСЬ_СЛУЧАЙНОЕ_ЗНАЧЕНИЕ_ИЗ_ГЕНЕРАТОРА
APP_DOMAIN=sochinenie.example.ru
APP_ORIGIN=https://sochinenie.example.ru
```

Замените пример на свой домен и код. В `APP_DOMAIN` протокола и пути нет. Не используйте показанный текст как реальный пароль или код.

3. Из каталога проекта выполните:

```bash
docker compose up -d --build
docker compose logs --tail=50 app caddy
```

Caddy получает и обновляет HTTPS-сертификат для заданного домена. Приложение доступно только через обратный прокси; порт 3000 не публикуется на сервере. База и видео сохраняются в постоянном томе `workshop-data`.

4. Откройте свой HTTPS-адрес, настройте преподавателя и три учётные записи. Не заполняйте реальными работами тестовую установку.
5. Проверьте один тест, отправку письменного ответа, возврат на доработку и загрузку видео с отдельного телефона через мобильный интернет.

В опубликованной версии Sites владельцу не нужен отдельный код, пока в окружении не задан `SETUP_TOKEN`: платформа ограничивает доступ к первоначальной настройке владельцем. Сами пароль преподавателя и учебные аккаунты всё равно создаются вами.

## Резервная копия и обновление

JSON-выгрузка в панели — переносимая копия учебных данных, но **не** полная копия установки: в ней нет хешей паролей, неотправленных черновиков и видеобайлов, автоматического импорта нет.

Для полной копии локального Node.js-приложения остановите сервер и скопируйте целиком каталог `data/`, включая SQLite и видео, в защищённое место. В Docker используйте команду из корня проекта:

```bash
mkdir -p backups
docker compose stop app
docker compose run --rm --no-deps --user root --entrypoint tar -v "$PWD/backups:/backup" app -czf /backup/workshop-data.tar.gz -C /app/data .
docker compose start app
```

Если архивирование завершилось ошибкой, всё равно запустите `docker compose start app`, устраните причину и повторите копирование. Храните резервную копию вне этого сервера. Не отправляйте её ученикам: она содержит все работы и учётные записи.

Перед обновлением сделайте полную копию, замените код и выполните `docker compose up -d --build`. Существующие миграции не редактируйте. Не запускайте `docker compose down -v`: эта команда удаляет постоянные тома. Для восстановления остановите приложение, восстановите файлы тома из полной копии и запустите прежнюю совместимую версию приложения. Для переноса локальной установки на VPS можно скопировать весь `data/` в каталог/том новой Node.js-установки до её первого запуска.

## Проверки и архитектура

```bash
npm run check
npm run build:standalone
npm test
```

Интеграционные тесты создают временную базу, генерируют тестовые пароли и затем удаляют всё тестовое состояние. Для теста видео нужен FFmpeg; для самого приложения он не нужен. Проверяются авторизация, три изолированных аккаунта, CSRF, приватность черновиков и результатов, все типы интерактивов, попытки, назначения, расписание, рецензирование, хранение после перезапуска, CRUD библиотеки, порядок уроков и защищённая передача видеодиапазонов.

- `app/workshop.tsx` — навигация и страницы ученика.
- `app/exercise.tsx` — все интерактивы и черновики.
- `app/admin.tsx` — панель преподавателя и визуальные редакторы.
- `lib/api.ts` — единый API и серверная проверка прав.
- `lib/security.ts` — пароли и сессионные токены.
- `lib/seed.ts` — стартовые материалы.
- `db/schema.ts`, `drizzle/` — схема и миграции.
- `standalone/server.ts` — Node.js, SQLite и файлы на диске.
- `worker/index.ts`, `app/api/` — адаптер размещённой версии, D1/R2.

Полезные первоисточники: [критерии ФИПИ](https://fipi.ru/itogovoe-sochinenie), [рекомендации OWASP по паролям](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [Node.js Crypto в Workers](https://developers.cloudflare.com/workers/runtime-apis/nodejs/crypto/).
